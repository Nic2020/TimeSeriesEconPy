# Julia DataEcon fixtures

`julia_monthly.daec` is generated by the actual TimeSeriesEcon.jl implementation.
`julia_monthly.toml` records the Julia/package/native versions, source and binary
hashes, fixture hash, and compiler-layout reference. It contains no local paths.

The single root object `/sample` is a nonempty monthly Float64 TSeries starting
at 2024M1, with values `[1.25, -2.5, 0.0, 4.75]` and no reconstruction attributes.
It ends at 2024M4. The native axis frequency is 32, first date code 24288, length
4, object class 2, object type 12, element type 4, element frequency 0, payload
32 bytes. Database IDs, timestamps and whole-file bytes are not interchange
equality requirements.

Use an isolated Julia project with the source checkout at
`fc0a0d01aed4903ea6c64b12d78d0bdf68468df6`, developed into that project with
`Pkg.develop(path=...)`. Resolve DataEcon_jll 0.4.0+0. The script checks that the
loaded package is exactly the supplied checkout and SHA, not a registry copy.

```text
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl generate <new-file.daec> <absolute-source-checkout>
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl verify <python-written-file.daec> <absolute-source-checkout>
```

Generation refuses to overwrite an existing path. `verify` checks a Python-written
file through Julia's public loader and native metadata. For that file, write the
same `/sample` using `open_dataecon` and close it before starting Julia.

The original fixture was generated with Julia 1.12.5 on Windows x86-64.
That Julia version emits an upstream `Int` constructor deprecation warning;
the interchange assertions pass. No upstream source was changed to silence it.

## Empty monthly fixture

`julia_empty_monthly.daec` contains `/empty` (Float64, 2024M1), `/empty_later`
(Float64, 2025M7) and `/empty_float32` (Float32, 2024M1; an unsupported-input
control). Its matching TOML file records the same provenance fields. All have
axis length and payload bytes zero, a NULL native payload, and `jeltype` set to
the literal Julia element type. Base metadata alone does not distinguish these
empty float widths. First-date codes are 24288 and 24306.

```text
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl generate-empty <new-file.daec> <absolute-source-checkout>
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl verify-empty <empty-fixture.daec> <absolute-source-checkout>
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl verify-wheel <python-written-file.daec> <absolute-source-checkout>
```

`verify-empty` records the pinned Julia loader's behavior: its `jeltype` handling
returns a plain Vector for these empty fixtures, despite the intact native range
axis. Python preserves the TSeries and accepts only the exact Float64 marker.
`verify-wheel` checks the existing nonempty sample plus Python-written `/empty`
and `/empty_later`. Python omits reconstruction markers, so Julia must return
dated empty Float64 TSeries. No evaluation of arbitrary type strings is used
by the Python reader. No change to the upstream Julia implementation is implied.

## Float64 scalar fixture

`julia_float64_scalars.daec` contains seven supported objects: `scalar_finite`
(1.25), `scalar_negative` (-2.5), `scalar_zero`, `scalar_negative_zero`,
`scalar_nan`, `scalar_positive_inf` and `scalar_negative_inf`. Each has metadata
class/type/frequency/bytes `(1,4,0,8)` and no per-object attributes. The
`scalar_float32` and `scalar_integer` controls exercise unsupported representations.
The matching TOML records provenance and compiler layout, including `scalar_t`.

Use `generate-scalars` and `verify-scalars` with the same script, output and
checkout arguments as above. `verify-wheel` now verifies all seven Python-written
Float64 scalars as well as the existing empty and nonempty series in one file.
Julia must preserve numerical values, NaN classification, infinities and signed
zero. Root DE_VERSION metadata is not a per-object reconstruction attribute.

## Quarterly Float64 fixture

`julia_quarterly.daec` and its TOML provenance are generated with the pinned
Julia checkout by `interchange.jl generate-quarterly <fresh-file> <checkout>`.
The 27 objects cover all three fiscal anchors, a year transition, negative/zero
years, native date limits, empty anchors at both limits, and the no-attribute
empty encoding. `verify-quarterly` checks the fixture again. The fixture contains
Julia's empty `jeltype=Float64` markers; Python preserves their stored date axes.

`verify-wheel` additionally checks Python-written quarterly objects for all
three anchors, including empty and boundary cases, alongside monthly series
and scalars. The wheel checker writes no quarterly reconstruction attributes.

## Annual Float64 fixture

`julia_annual.daec` and its TOML provenance are generated by the pinned Julia
checkout with `interchange.jl generate-annual <fresh-file> <checkout>`.
`verify-annual` verifies it again. Its 132 objects cover twelve fiscal year-end
months, year transitions, negative/zero years, the signed 32-bit limits and
empty anchors with and without Julia's `jeltype=Float64` marker.

`verify-wheel` additionally checks 96 Python-written annual objects in the
existing combined interchange file. Every fiscal ending is checked for type,
values, frequency and first/last dates, including empty anchors at both limits.
Python writes no reconstruction attributes for these annual series.

## Half-yearly Float64 fixture

`julia_halfyearly.daec` and its TOML provenance are generated by the pinned Julia
checkout with `interchange.jl generate-halfyearly <fresh-file> <checkout>`.
`verify-halfyearly` verifies it again. Its 72 objects cover six half-year
endings, year transitions, negative/zero years, the reliable native limits
`-65600` and `2147483647`, and empty anchors with and without Julia's
`jeltype=Float64` marker. Each ending also stores `below_minimum` at code
`-65601`: Julia writes it intact, but the pinned loader decodes another date
and warns. Python rejects that stored code instead of returning a wrong date.

`verify-wheel` additionally checks 48 Python-written half-yearly objects in the
existing combined interchange file. Every ending is checked for type, values,
frequency and first/last dates, including empty anchors at both limits.

## Int64 scalar fixture

`julia_int64_scalars.daec` and its TOML provenance are generated by the pinned
Julia checkout with `interchange.jl generate-int64 <fresh-file> <checkout>`;
`verify-int64` verifies it again. Fourteen `int_*` objects are written by the
Julia writer (zero, small values, 2^53 and its neighbors, 2^62+1, both signed
64-bit endpoints and their neighbors) and four `int_native_*` objects directly
through the C ABI with the same encoding Python uses: metadata
class/type/frequency/bytes `(1,1,0,8)`, little-endian two's complement and no
attributes. Eight `ctl_*` controls record neighboring representations that
Python rejects: a Bool (one byte, which Julia reloads as `Int8`), Int32,
Int128, UInt64, a monthly `Duration` (type 1 with a frequency), a monthly
`MIT` date (type 3), a `Rational` (Float64 payload plus `jtype`) and a String.

`verify-wheel` additionally checks the fourteen Python-written Int64 objects
in the existing combined interchange file: Julia must load each as an `Int64`
with the exact value and no reconstruction attribute.

## String scalar fixture

`julia_string_scalars.daec` and its TOML provenance are generated by the pinned
Julia checkout with `interchange.jl generate-strings <fresh-file> <checkout>`;
`verify-strings` verifies it again. Fifteen `str_*` objects are written by the
Julia writer: metadata class/type/frequency/bytes `(1,6,0,n)`, UTF-8 bytes plus
one NUL terminator, no attributes. Controls record Julia-written values that
Python does not support yet and rejects rather than misreads:
`ctl_str_embedded_nul` (Julia stores `a\0b\0` and loads `"a"`),
`ctl_str_invalid_utf8` (Julia returns the invalid bytes unchecked) and
`ctl_symbol` (a `Symbol` stored as a string with `jtype="Symbol"`). Native
objects written directly through the C ABI cover a payload without a
terminator, a NULL payload (which Julia cannot load either), a lone NUL (the
empty string) and a string object carrying a frequency code.

`verify-wheel` additionally checks the fifteen Python-written string objects in
the combined interchange file: Julia must load each as a `String` with the
exact bytes and no attribute.

## Date and duration scalar fixture

`julia_date_scalars.daec` and its TOML provenance are generated by the pinned
Julia checkout with `interchange.jl generate-dates <fresh-file> <checkout>`;
`verify-dates` verifies it again. For each of the 22 year/period frequency
families (monthly, three quarterly anchors, six half-yearly endings, twelve
annual endings) the Julia writer stores six `mit_*` dates (typical, year
boundary, -1, 0, the reliable minimum and 2147483647) with metadata
`(1,3,code,8)` and six `dur_*` durations (0, 1, -1, 2^53+1 and both signed
64-bit endpoints) with metadata `(1,1,code,8)`. Every family with more than
one period per year also stores `ctl_mit_*_below_minimum`, which Julia writes
intact and then misdates on load with a warning; Python rejects it. Further
controls cover `Unit`, `Daily`, `BDaily` and `Weekly` scalars (now supported;
see the next fixture), Julia's non-canonical `Quarterly{4}` anchor (stored as
code 65) and native encodings Julia never writes: a date without a frequency,
four-byte payloads, mixed frequency bits and a bare family code.

`verify-wheel` additionally checks the 264 Python-written date and duration
objects in the combined interchange file: Julia must load each as the exact
`MIT{F}` or `Duration{F}` with the expected integer code and no attribute.

## Unit and calendar scalar fixture

`julia_unit_calendar_scalars.daec` and its TOML provenance are generated with
`interchange.jl generate-calendar <fresh-file> <checkout>`; `verify-calendar`
verifies it again. For `Daily`, `BDaily` and each `Weekly{1..7}` end day the
Julia writer stores thirteen `mit_*` dates (15 January 2024, the 2024/2025
year boundary, leap day 2024, 1 January 0001, a year-zero date, a negative
year, -1, 0, both endpoints of the verified native window, 31 December 9999
and a date in year 10000) with metadata `(1,3,code,8)` and six `dur_*`
durations with `(1,1,code,8)`; `Unit` stores eleven `mit_u_*` dates and
`dur_u_*` durations with codes 11, including both signed 64-bit endpoints.
Controls: `ctl_mit_{d,b,w7}_below_window` (Julia stores each with a "codes
differ" warning; daily and business daily reload as another date, weekly by
coincidence as the same one; Python rejects all three), `ctl_weekly8_mit`
(Julia's `Weekly{8}` stored as code 17), and native encodings Julia never
writes: the Sunday alias 16 (Julia loads `Weekly{0}`), the unused code 14, the
weekly anchor 24, a four-byte unit payload, the first daily code above the
window (Julia reloads it unchanged) and an Int32-wrapped daily code.

`verify-wheel` additionally checks the 193 Python-written unit and calendar
objects in the combined interchange file.

## Calendar series fixture

`julia_calendar_series.daec` and its TOML provenance are generated with
`interchange.jl generate-calendar-series <fresh-file> <checkout>`;
`verify-calendar-series` verifies it again. For `Daily`, `BDaily` and each
`Weekly{1..7}` end day the Julia writer stores thirteen `cs_*` Float64
TSeries: four values from 30 December 2024 (crossing the year end), three from
28 February 2024 (leap day), two from Friday 12 January 2024 (a weekend for
business days), two from code -1, one at code 0, one at each verified window
endpoint, five from 31 December 9999 into year 10000, two values from the
window maximum and a thousand values (`0.25k`) from 499 codes before it (both
run past the window; only the first date is packed), and empty series
anchored at 15 January 2024 and at both endpoints. Metadata is
`(2,12,4,0,1,n,code,first,8n)`; Julia's empty series carry `jeltype =
"Float64"`, nonempty ones no attribute. Control per family:
`ctl_*_below_window` (Julia stores the first date with a "codes differ"
warning; daily and business daily reload another date), and native objects
Julia never writes: `cs_*_native_empty` (no marker, Julia reloads a dated
empty TSeries), `cs_*_native_first_above_maximum` (Julia reloads it unchanged)
and `cs_*_native_int32_wrap` (Julia reloads the wrapped code with a warning).
Singles: `ctl_weekly8_series` (Julia's `Weekly{8}` stored as code 17),
`native_axis_weekly16`/`weekly24`/`freq14` and `ctl_empty_float32_daily`
(`jeltype = "Float32"`). Python rejects every control except the marker-free
native empties and the collapsed `Weekly{8}` series.

`verify-wheel` additionally checks the 117 Python-written `cs_*` series in
the combined interchange file.

## Numeric width scalar fixture

`julia_numeric_widths.daec` contains 90 Julia-written `w_<group>_<case>`
objects covering Float16/Float32 (13 each: zero, signed zero, typical, 0.1,
both extremes, smallest normal and subnormal, NaN, infinities, a
precision-loss value and pi), Int8/Int16/Int32 (8 each including both
endpoints and their neighbours), UInt8..UInt64 (6 each including the maximum
and the high bit) and ComplexF32/ComplexF64 (8 each with signed-zero, NaN,
infinite, extreme and subnormal components); fifteen `wn_*` objects written
directly through the C ABI with the same metadata; and controls `wctl_*`:
Int128/UInt128 (7 and the maxima), ComplexF16, `true`/`false` (stored as
`(1,1,0,1)`, byte-identical to the `Int8` twins, reloaded by Julia as
`Int8`), `8 + 3im` (ComplexF64 plus `jtype = "Complex{Int64}"`) and
`wctl_marker_true` (an Int8 byte with a hand-set `jtype = "Bool"` that Julia
reloads as `true`; Julia never writes that marker itself). Every supported
object has metadata `(1,type,0,sizeof)` with type 1/2/4/5 and no attributes.

```text
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl generate-widths <new-file.daec> <absolute-source-checkout>
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl verify-widths <widths-fixture.daec> <absolute-source-checkout>
```

`verify-wheel` also checks the Python-written `w_*` objects (plus
`w_pyc_plain`, a Python `complex` stored as ComplexF64) for the same type and
bits.

## File operations fixture

`julia_file_operations.daec` records Julia's delete, overwrite and truncate
behavior. Julia wrote two objects, truncated the file (so ids restart at 1),
then wrote catalog `keep` (`/keep/z` = 4, `/keep/inner/w` = 5), scalars `a`
(Int64 1), `b` ("text"), `r` (`1//2`, with a `jtype` attribute), series `s`
and `s2` (2024M1, `[1.0, 2.0, 3.0]`, sharing one axis), catalog
`deleted_catalog` with nested content, and scalar `overwritten_series`
(Int64 1); deleted `b`, `s`, `r` and `deleted_catalog` (recursively); then
reopened with `overwrite=true` and replaced `a` by the string `"replaced"`
and `overwritten_series` by the series. The final root holds `keep`, `a`,
`s2` and `overwritten_series`; no attribute other than `DE_VERSION` remains;
the single axis row survived the deletion of `s`. Python tests use copies of
this fixture for recursive catalog deletion and overwrite refusals.

```text
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl generate-fileops <new-file.daec> <absolute-source-checkout>
julia --startup-file=no --project=<isolated-project> tests/dataecon/fixtures/interchange.jl verify-fileops <fileops-fixture.daec> <absolute-source-checkout>
```

`verify-wheel` also checks the Python-written `fo_overwritten` (string
`"two"`), the absence of `fo_deleted`, `fo_series_overwritten` (a series),
and the auxiliary `fileops/<output>-fileops.daec` file that Python populated,
truncated with mode `"w"` and refilled (`after_truncate` = 42 with id 1, plus
a series). Auxiliary outputs sit in the `fileops` subdirectory so that the
workflow's `*.daec` glob over the interchange directory still finds exactly
one primary file; `verify-wheel` asserts that layout.
